Metric audit: the score, before the model

Re-derived from the published equations and checked against the problem page's own worked example. python scripts/verify_metric.py; raw output in docs/evidence/metric_audit.json.

Transcription

k(d)  = max(1 - d/R, 0),  R = 300 m
TP_w  = sum over truth pixels of max over the kernel of pred(x)*k(d(x,g))
FP_w  = sum over predicted pixels of pred(x)*(1 - max_g k(d(x,g)))
FN_w  = sum over truth pixels of (1 - that same max)
DTI   = TP_w / (TP_w + 0.2*FP_w + 0.8*FN_w)

Official worked example: TP_w 3.00, FP_w 1.89, FN_w 2.00 → 3.00 / (3.00 + 0.2·1.89 + 0.8·2.00) = 3.00 / 4.978 = 0.6027 → 0.60, which is the 0.60 printed on the page.

The four consequences, each proved

  1. Reduction. TP_w + FN_w = |G| exactly, so DTI = 1/(0.8/R_w + 0.2/P_w): a weighted harmonic mean of weighted recall (weight 0.8) and weighted precision (weight 0.2). Residual 5.6e-17 on random rasters.
  2. Marginal rule. A block of predictions pays off iff its own weighted precision exceeds 0.2 × DTI. At the current leader's 0.3168 that is a bar of 0.0634.
  3. Binary optimum. DTI(t·p) is strictly increasing in t, so pushing values toward 1 always helps and the best map is 0/1; the graded field is only a ranking device.
  4. Recall versus precision. d ln DTI ratio is 4P/R, so a relative recall gain beats an equal relative precision gain whenever P > R/4.

Why this dictates a much wider map than a 0.5 cutoff

A lone pixel pays for itself out to 281 m (2.81 px) at DTI 0.3168, and the bar a block must clear is only 6.3% precision. Suppressing anything below a calibrated 0.5 throws away mass that the metric still pays for. That prediction is what the holdout then measured.
